# вишлист

уютное приложение-вишлист на двоих: две вкладки — «никита» (тёмно-зелёная) и «ника» (нежно-розовая).

## что умеет

- две вкладки с разными темами, переключение в одно касание
- добавление, редактирование и удаление вишей
- попап с загрузкой фото, названием и необязательной ссылкой на покупку
- все картинки автоматически обрезаются в один квадратный формат (640×640), поэтому карточки выглядят одинаково
- полностью адаптивная вёрстка для телефонов
- всё на русском, без заглавных букв
- маленькие зверята (лягушка, улитка, котёнок, фея и панда) изредка проползают по кнопкам — примерно раз в минуту на несколько секунд
- синхронизация между устройствами через firebase (firestore): открыл сайт на телефоне и на ноутбуке — список один и тот же

## как это работает

это статическая страница без сборки и без своего сервера. фото обрезаются в квадрат 512×512
и хранятся вместе с вишем в виде data url (около 40–60 кб на картинку).

- **без настроек firebase** — виши лежат в `localStorage` браузера, у каждой вкладки свой список
- **с настройками firebase** — виши лежат в firestore и приходят на все устройства сами,
  а `localStorage` работает как offline-копия: без сети список виден и его можно пополнять,
  всё несинхронизированное уедет в облако, когда сеть вернётся

структура в firestore: `lists/{никита|ника}/wishes/{id виша}`.

## как включить синхронизацию

1. заходишь на `console.firebase.google.com` и создаёшь проект (google analytics не нужен)
2. в проекте: `build → firestore database → create database`, режим `production`,
   регион — ближайший (например `europe-west3`)
3. на вкладке `rules` вставляешь правила и жмёшь `publish`:

   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /lists/{person}/wishes/{wish} {
         allow read, write: if person in ['nikita', 'nika'];
       }
     }
   }
   ```

4. `project settings → your apps → web (</>)`, регистрируешь приложение и копируешь объект
   `firebaseConfig`
5. вставляешь его поля в `firebase-config.js` и пушишь — всё, синхронизация работает

про безопасность: ключи firebase публичные, это нормально, но правила выше открывают
списки любому, кто знает адрес проекта. для вишлиста на двоих этого достаточно;
если захочется закрыть — включается firebase authentication (например вход по google)
и в правилах вместо `if person in [...]` пишется проверка `request.auth`.

бесплатного тарифа firestore (50 тысяч чтений в день) хватит с огромным запасом.

## запуск локально

просто открой `index.html` в браузере, либо:

```
python3 -m http.server 8000
```

и зайди на `http://localhost:8000`.

## публикация

**github pages:** нужен один ручной шаг — в настройках репозитория
`settings → pages → source` выбери `github actions` (сам воркфлоу включить pages не может,
у токена нет таких прав). после этого запусти воркфлоу `deploy to github pages`
на вкладке `actions` или просто сделай пуш — сайт опубликуется на
`https://kanon402.github.io/wish/`.

**netlify:** подключи репозиторий, каталог публикации — корень (`.`), команда сборки не нужна
(это уже прописано в `netlify.toml`). можно и просто перетащить папку в netlify drop.

## файлы

- `index.html` — разметка
- `styles.css` — темы и адаптив
- `app.js` — логика: хранение, синхронизация, попапы, обработка фото, зверята
- `firebase-config.js` — настройки проекта firebase (пустой = работа без синхронизации)
